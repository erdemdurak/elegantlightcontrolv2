# Apple CarPlay — outcome

**Resolved 2026-08-01.** Superseded the original plan, which was written before the protocol
was known and before iOS 26.

## What was wanted

Control the ambient lighting from the car without handling the phone.

## What is actually possible

| | Reaches the head-unit screen | Control | Entitlement |
| --- | --- | --- | --- |
| Full CarPlay app | yes | yes | **Apple grant required — refused for this category** |
| CarPlay Dashboard widget (iOS 26) | yes | no, display-only | none |
| Siri / App Intents | no | **yes** | none |

## Why a full CarPlay app is out

The entitlement covers a fixed set of categories — audio, communication, navigation, EV
charging, parking, fueling, quick food ordering, driving task, automaker — and an aftermarket
lighting kit fits none of them.

It is not something that can be worked around locally. The entitlement has to be present in the
**provisioning profile**, and profiles are generated by Apple's servers from the capabilities
enabled on the App ID; iOS validates the profile at install. There is nothing to sign because
Apple never issues it. Keeping the app private does not help — Apple's criteria expect an app
that is substantively built and genuinely distributed.

The often-cited workaround — adding `com.apple.developer.carplay-maps` to the entitlements file
by hand — works **only in the Xcode simulator**. It never reaches real head-unit hardware.

## What shipped instead

**Siri via App Intents**, confirmed working in the car on 2026-08-01. Colour, preset, mode,
brightness and power, hands-free through the car's microphone while CarPlay is connected.

Supporting pieces that made it usable:

- Auto-reconnect to the last controller, without which a spoken command reaches a disconnected
  app and does nothing.
- CarPlay detection from the audio route (`AVAudioSessionPortCarAudio`), so the app knows it is
  in the car.
- Day/night profiles applied automatically on connect.
- A Shortcuts automation on *CarPlay connects* that opens the app, which then applies the right
  profile by itself.

## Known limits

- **Area cannot be spoken.** AppShortcut phrases accept one parameter each, so "set the vents to
  red" is impossible. Area remains settable in the Shortcuts app.
- **Brightness has no spoken phrase** — an `Int` cannot appear in a phrase at all.
- **The app foregrounds** when an intent runs (`openAppWhenRun`). Removing that means
  reimplementing the Lenze protocol in Swift with CoreBluetooth — Task 1c, deferred until the
  behaviour proves annoying in practice.

## Still open

- **1c**, above.
- **Driving-task entitlement request** — the only category an in-car accessory could argue for.
  Free to submit at developer.apple.com/carplay, low odds, and the only path that would ever put
  a real CarPlay app on the head unit.
- **A widget** would put cabin state on the CarPlay screen with no entitlement, display-only.
  Not built; not wanted so far.
